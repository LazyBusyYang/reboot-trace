SQLite 数据库设计

面向原子快照、跨生命周期查询与严格空间预算的数据模型。

首页需求架构数据库接口前端部署

1. 实体关系

logical target 1 ── N container lifecycle
                 ├── N snapshot
                 │      ├── 1 system_sample
                 │      ├── N process_sample ── N process_rank
                 │      └── N user_sample
                 ├── N event（可选关联 snapshot）
                 └── N service_session

process_sample 保存一次进程观测；process_rank 表示同一观测入选 CPU、RSS、Swap、I/O 中哪些榜单，避免一进程多榜重复存储命令行。事件必须属于生命周期，只有与某次采样直接相关时才填写可空的 snapshot_id。

2. 表设计

host

字段类型说明
idTEXT PK稳定 host_id，首次启动生成并保存在数据卷。
hostnameTEXT当前主机名。
created_at_msINTEGERUnix 毫秒。

lifecycle

字段类型说明
idINTEGER PK内部自增键。
host_id / lifecycle_keyTEXT逻辑目标与容器实例生命周期联合唯一键。
container_instance_idTEXT NULL目标容器根 overlay 中的实例 UUID。
pid1_start_ticks / pid_namespace_inode / cgroup_hashINTEGER/TEXTPID 1 指纹；与 marker 同时变化才构成 confirmed。
boot_idTEXT NOT NULLLinux kernel boot ID，仅作辅助证据。
detection_method / detection_confidenceTEXT生命周期判定方法与 confirmed、probable、unknown 等置信度。
started_at_ms / last_seen_at_msINTEGER容器 PID 1 推算启动与最后快照时间。
terminationTEXTactive、clean_shutdown_observed、unclean_or_unknown。
summary_jsonTEXT证据保留状态。

snapshot

字段类型说明
idINTEGER PK快照 ID。
lifecycle_idINTEGER FK所属生命周期。
captured_at_msINTEGER采样时间。
scheduled_at_msINTEGER计划时间，用于计算调度漂移。
duration_msINTEGER采集耗时。
sample_interval_msINTEGER相邻有效样本间隔。
detail_levelTEXTfull、downsampled、final、summary_only。
persistence_stateTEXT该快照提交时的持久化状态；用于重启后区分完整与降级证据。

system_sample

以 snapshot_id 为主键，保存 CPU 各状态、load1/5/15、内存、Swap、磁盘、inode、进程/线程总数、CPU/memory/I/O PSI、uptime 及 capability 位图。数值使用 INTEGER 字节或 REAL 比例，不保存带单位字符串。

process_sample

核心字段说明
snapshot_id, pid, create_time_ms联合唯一识别一次进程观测，避免 PID 复用。
ppid, uid, username, comm, state, threads身份与状态。
cpu_percent, rss_bytes, swap_bytesCPU 与内存。
read_bps, write_bps, read_bytes, write_bytesI/O 速率和累积量。
cmdline_redactedTEXT NOT NULL；脱敏后最多 4096 UTF-8 字节。原始命令永不入库。
cmdline_hash完整脱敏后、截断前规范化命令的 SHA-256；不得基于原始命令。
truncated / redaction_status是否截断；脱敏状态为 redacted、no_sensitive_value 或 failed_closed。

process_rank

(snapshot_id, pid, create_time_ms, dimension) 为主键，另存 rank 与 value；dimension 限定为 cpu、rss、swap、read、write。

user_sample、event 与 service_session

user_sample 以 snapshot、uid 聚合资源。event 必须包含 lifecycle_id、occurred_at_ms、受限枚举 type 和限长 details_json，可选 snapshot_id；类型包括 oom_observed、sampling_delay、collector_error、retention、collector_started、collector_stopped、host_shutdown_observed、container_instance_changed、identity_conflict、identity_baseline_established 和 collection_gap。service_session 记录同一 lifecycle_key 内采集器的启动、停止与实例版本，不参与生命周期终止判断。

3. 索引

UNIQUE lifecycle(host_id, lifecycle_key)
INDEX snapshot(lifecycle_id, captured_at_ms DESC)
INDEX process_sample(snapshot_id, cpu_percent DESC)
INDEX process_sample(snapshot_id, rss_bytes DESC)
INDEX process_sample(snapshot_id, uid)
INDEX process_rank(snapshot_id, dimension, rank)
INDEX event(lifecycle_id, occurred_at_ms DESC)
INDEX service_session(lifecycle_id, started_at_ms DESC)

所有子表外键均启用 ON DELETE CASCADE；event.snapshot_id 使用 ON DELETE SET NULL，确保降采样删除快照时保留生命周期事件。不为完整命令行建普通索引。若未来需要搜索，采用显式、可关闭的 FTS 表并计入空间预算。

4. 事务和 SQLite 参数

  • 首次建库、创建任何表之前设置固定 page_size 和 auto_vacuum=INCREMENTAL；启用 foreign_keys、WAL 和 busy timeout。
  • 每个快照使用 BEGIN IMMEDIATE 到 COMMIT 的单事务。HTTP 长查询使用只读连接，写入连接保持单写者。
  • synchronous 默认 FULL；只有经断电测试验证并由配置显式选择时才允许 NORMAL。
  • 数据库 schema 使用 PRAGMA user_version 迁移，迁移前检查可用空间。
  • 设置受预算约束的 journal_size_limit 与 max_page_count。不能承诺文件系统或硬件在断电时绝对不丢失；UI 展示最后成功提交时间。

5. 指标存储语义

指标单位与范围缺失规则
host_cpu_percentREAL，0～100，全机归一化首次或读取失败为 null
process/user cpu_percentREAL，单核 100%，可超过 100首次、身份变化或无有效间隔为 null
read_bps/write_bpsREAL，bytes/s首次、计数器回退、权限不足为 null
RSS/Swap/磁盘INTEGER bytes不支持或权限不足为 null，不用 0 代替
时间INTEGER Unix ms UTC速率差值另用单调时钟计算

Top-N 排序忽略 null；0 表示成功观测且值确为零。UID 是关联键，username 仅是当时的显示快照。

6. 50 MiB 空间治理

配置值是应用受管文件预算，覆盖数据库主文件、-wal、-shm 及同目录临时文件。默认 50 MiB；软阈值默认取预算的 85%。写入安全余量取 2 MiB 与最近观测到的最大完整快照事务体积两倍中的较大值，并随运行更新。

  1. 达到软阈值或剩余空间小于安全余量：停止接受长查询，执行 WAL checkpoint；无活动读事务时使用 TRUNCATE 模式。
  2. 删除最老生命周期中的非末尾高频快照，随后分批执行 incremental vacuum 并重新测量实际文件。
  3. 仍不足时仅保留老生命周期的降采样点、最终窗口和摘要，再按生命周期从旧到新清理普通明细。
  4. 普通明细耗尽后仍超压时，把最老 final 的进程与用户明细清除并标记为 system-only，优先保护最新历史 final；若 final 集合自身超过硬预算，再同样降级最新历史 final。降级后的 system-only 快照可在下一轮被删除，但 lifecycle 元数据和 summary 继续保留。
  5. 若完整快照无法安全提交，先降低 Top N，再降级为 system_sample + user summary；每次降级必须可通过 status 查询。
  6. 连最小快照也无法在预算内提交时暂停持久化、保留内存最新状态并把 persistence_state 暴露为 paused，不得继续尝试写满磁盘。

max_page_count 只约束数据库主文件，不能替代对 WAL/SHM 的实际测量。文件系统分配粒度和异常中断可能造成短暂误差，因此验收以应用停止新增前不越过“预算减安全余量”为准，而不是宣称操作系统层面的绝对字节硬限。容量规划必须根据采样间隔、各维度 Top N 的去重后并集、命令行平均长度和最终窗口计算预计保留时长。
