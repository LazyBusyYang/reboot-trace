项目架构

每个目标容器拥有独立、可离线工作的取证后端；一个 Vue 前端直接聚合多个后端的展示结果。

首页需求架构数据库接口前端部署

1. 总体拓扑

┌──────────────────── Vue 前端 ────────────────────┐
│ 运行时后端列表 / 并行查询 / 节点状态 / 图表与对比 │
└───────┬────────────────┬────────────────┬────────┘
        │ REST           │ REST           │ REST
┌───────▼───────┐ ┌──────▼────────┐ ┌─────▼─────────┐
│ dev-01 后端   │ │ dev-02 后端   │ │ dev-N 后端    │
│ Collector     │ │ Collector     │ │ Collector     │
│ FastAPI       │ │ FastAPI       │ │ FastAPI       │
│ SQLite volume │ │ SQLite volume │ │ SQLite volume │
└───────────────┘ └───────────────┘ └───────────────┘

前端不是持久化中心，也不复制原始数据。每个后端是所属主机数据的权威来源。某台机器离线时，前端标记该节点不可用并继续展示其他节点。

2. 后端组件

组件职责
Lifecycle Manager联合实例 UUID、PID 1 指纹和数据库历史恢复或建立容器生命周期；kernel boot ID 只作辅助证据，采集器启停只记录 service event。
Collector固定调度采样主机和进程，保存上次计数器以计算 CPU/I/O 差值。
Snapshot Assembler合并系统、进程 Top-N、用户汇总和事件，形成完整快照。
SQLite Repository串行协调活动库写入、跨分段查询、活动库轮转、空间核算和整段清理。
FastAPI提供健康、能力、生命周期、快照、排行、用户和对比接口。
Retention Manager按软/硬阈值治理活动库、历史分段、manifest 和 quarantine 总空间并记录丢弃统计。

采集任务、保留任务和 HTTP 服务逻辑分离。API 读取 SQLite 或最新内存快照，绝不因一次前端刷新触发全量进程扫描。

3. 多后端前端模型

前端容器启动时加载 /config/runtime-config.json，示例：

{
  "backends": [
    {"id":"dev-01","name":"Maoshanwang_dev_01","baseUrl":"https://dev-01.example/api/v1"},
    {"id":"dev-02","name":"Maoshanwang_dev_02","baseUrl":"https://dev-02.example/api/v1"}
  ],
  "requestTimeoutMs": 8000,
  "refreshIntervalMs": 5000
}
  • id 在前端配置内唯一且稳定，不使用数组位置作为身份。
  • baseUrl 指向每台主机后端的 HTTPS Ingress；浏览器直接跨域请求，不经过前端代理。
  • 启动后并行请求各后端 /status 与 /latest，以服务端返回的 host_id 校验配置并取得总览指标。
  • 请求使用 Promise.allSettled 类型语义，分别呈现成功、超时、Ingress 拒绝和网络失败。
  • 跨主机时间轴以 UTC 时间戳传输，浏览器使用 status.server_time_ms 与往返时间估算节点时钟偏差，再按用户时区显示。
  • 第一版后端无应用层登录鉴权，不传 Authorization 和 Cookie；Ingress 负责 TLS，网络策略/私网可达性限制访问范围，后端 CORS 只允许明确配置的前端 Origin。

4. 关键时序

正常采样

  1. 调度器记录预期触发时间和实际开始时间，并复核 PID 1 指纹。
  2. 并行读取系统指标与进程表，并以先前计数器计算速率。
  3. 建立各维度 Top-N 与用户汇总。
  4. 使用一个 SQLite 事务写入 snapshot 及全部子记录。
  5. 提交成功后更新内存“最后持久化快照”；失败则记录错误并保持旧值。

服务启动与新生命周期

  1. 验证后端与目标 PID 1 的 PID/mount namespace 同源，读取根 overlay marker、PID 1 指纹和 kernel boot ID。
  2. marker 与 PID 1 指纹均未变化时恢复原 lifecycle_key，仅记录 collector_started 或采集空窗。
  3. marker 与 PID 1 指纹同时变化时以 confirmed 创建新生命周期；仅任一信号变化时以 probable 创建并记录 marker 变化或身份冲突。
  4. 仅 kernel boot ID 变化或仅网络断联不创建新生命周期。未观察到可信正常退出证据时使用 unclean_or_unknown，并保护 final 证据窗口。

5. 故障边界

  • 硬断电只能保住最近一次成功提交，无法捕获断电瞬间。
  • 后端必须作为普通进程运行在目标容器内；兄弟容器、host PID 或宿主 procfs 不属于支持的身份拓扑。
  • 无应用层鉴权意味着任何能访问 Ingress 的客户端都能读取脱敏取证数据；Ingress 必须位于受控网络并使用 TLS。
  • 50 MiB 是预算而非固定保存时长，保存时长取决于进程数量、采样周期、Top N 与命令长度。
