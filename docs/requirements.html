项目需求

围绕“重启后仍能看到上一个生命周期终止前发生了什么”定义产品能力。

首页需求架构数据库接口前端部署

1. 背景与目标

Maoshanwang_dev_* 跳板机频繁重启，怀疑大型程序造成 CPU、内存或 I/O 压力。本项目在每台主机本地持续采样、持久化并展示证据，帮助运维人员人工判断原因。

一次操作系统启动至下一次启动之间定义为一个生命周期，以 Linux boot_id 唯一标识。新生命周期不得覆盖旧生命周期。

2. 功能需求

2.1 采集

  • 后台周期采集，不在 API 请求过程中扫描全部进程；默认周期建议 5 秒且可配置。
  • 记录主机 CPU、内存、Swap、load average、磁盘空间与 inode、进程/线程总数。
  • 记录 CPU、RSS、Swap、磁盘读写等维度各自 Top 50 进程；Top N 可配置。
  • 记录进程 PID、创建时间、所属用户、可执行名、父 PID、状态、线程数、命令与参数。
  • 按用户汇总 CPU、RSS、Swap、I/O、进程数和线程数。
  • 记录 CPU、内存和 I/O PSI；尽可能采集 OOM、采样延迟、服务启停等事件。
  • CPU 与 I/O 速率必须由相邻采样差值计算，首次观测不得伪造速率。

2.2 生命周期与取证

  • 启动时读取 /proc/sys/kernel/random/boot_id，自动建立或恢复当前生命周期。
  • 后端服务重启但 boot_id 未变化时，必须恢复同一生命周期；服务启停只记录事件，不得结束操作系统生命周期。
  • 仅当观察到新的 boot_id 时封存上一生命周期：存在可信操作系统关机证据时标记为 clean_shutdown_observed，否则标记为 unclean_or_unknown，后者不得等同于已证明异常重启。
  • 一次快照的系统、用户和进程数据必须在同一事务中原子提交。
  • 提供生命周期列表、详情、最终快照、时间序列、进程排行、用户汇总和快照对比。

2.3 前端

  • Vue SPA 与后端独立部署。
  • 前端启动时通过运行时配置获得多个后端服务，不要求重新构建镜像。
  • 并行查询多个跳板机后端，展示各节点在线状态；单节点失败不得阻断其他节点。
  • 支持主机概览、生命周期列表、生命周期趋势、最终快照和双快照对比。

3. 非功能需求

方面要求
磁盘默认受管文件预算 50 MiB，可配置；预算覆盖 DB、WAL、SHM 与同目录临时文件。软阈值触发清理，写入前预留安全空间，无法安全提交时暂停明细持久化。
开销采集器必须缓存静态信息、限制命令长度并避免自身成为资源故障诱因。
一致性SQLite 事务、WAL checkpoint 和合理同步等级；明确最后成功落盘时间。
安全原始命令行不落盘；仅保存脱敏后最多 4096 字节。后端第一版不提供登录鉴权，由各主机 Ingress 提供 TLS，并通过网络可达性和精确 CORS Origin 限制访问。
兼容目标为使用 procfs 的 Linux；缺少 PSI、Swap 或 I/O 字段时返回 capability 信息而非失败。

4. 保留与降采样

  1. 当前生命周期最近窗口保留完整高频快照。
  2. 历史生命周期优先保留终止前 10 分钟的完整记录。
  3. 更早的中间记录先降采样，再按完整生命周期从旧到新删除。
  4. final 快照采用分级保护：普通历史明细清理后仍超压时，先把更老 final 降为 system-only；若 final 集合自身超过硬预算，再降级最新历史 final，仅保留生命周期摘要。
  5. 尽量保留每个生命周期元数据、最终若干快照和摘要；硬限制优先于“永久”承诺。

5. 指标口径

  • 进程 CPU 百分比按相邻有效采样间的进程 CPU 时间增量除以单调时钟增量计算，以“单核 100%”表示，因此多线程进程和用户聚合值可以超过 100%；主机总 CPU 使用率归一化为 0～100%。
  • 进程 I/O 速率按累计字节增量除以单调时钟间隔计算；首次观测、PID 身份变化、计数器回退或读取失败时为 null，不得伪造为 0。
  • RSS、Swap、磁盘空间等瞬时量以采样时值记录。字段不受支持或权限不足时为 null，并在 capabilities 中说明原因。
  • 所有持久化时间使用 Unix 毫秒 UTC；速率计算使用单调时钟，避免系统时钟校准制造负速率。
  • UID 是用户身份的权威值，username 是采样时的 best-effort 显示值，不作为关联键。

6. 命令行保护

  • 采集器读取 /proc/{pid}/cmdline 后必须先在内存中脱敏，再序列化和截断；原始字节不得写入数据库、日志、事件或错误响应。
  • 默认和硬上限均为 4096 UTF-8 字节；截断不得产生非法 UTF-8，并设置 truncated=true。
  • 识别 password、passwd、token、secret、api-key、authorization、credential 等大小写不敏感的 --key=value、--key value 和常见 URI 凭证形式；值替换为固定文本 [REDACTED]。
  • cmdline_hash 对“完整脱敏后、截断前”的规范化命令计算 SHA-256，用于判断命令是否相同；不得对原始命令计算或保存可被离线猜测利用的哈希。
  • 无法可靠解析时采用保守脱敏并允许整条命令显示为 [REDACTION_FAILED]，同时记录不含原文的计数指标。

7. 第一版验收标准

  • 后端服务重启且 boot_id 未变化时继续使用原生命周期；主机重启后能查询上一 boot_id 的最终完整快照。
  • CPU/RSS/Swap/I/O Top 50 互相独立，且进程通过 pid + create_time 区分。
  • 写入超过软阈值后可自动回收；无法在预算内安全提交时进入明确、可查询的持久化降级状态。
  • 一个前端至少能配置并展示两个 Ingress 后端，浏览器跨域直连；任一后端离线时其余主机仍可用。
  • 数据库、API 和日志中不存在原始命令行，脱敏命令不超过 4096 UTF-8 字节。
  • 镜像重建不影响挂载卷内的 SQLite 数据。
