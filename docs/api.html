REST API 设计

JSON 是权威查询形式；接口围绕主机、生命周期与快照组织，适合 Vue 多后端并行访问。

首页需求架构数据库接口前端部署

1. 约定

  • 前缀：/api/v1；响应 Content-Type: application/json，并返回 api_version: "1" 与整数 schema_version。
  • 时间字段使用 Unix 毫秒 UTC 并以 _at_ms 结尾；持续时间以 _ms 结尾。容量统一为 bytes，速率统一为 bytes/s，比例字段以 _percent 结尾。
  • 列表使用不透明 cursor 分页，返回 items、next_cursor；limit 默认 100，最大 1000。cursor 绑定筛选与排序，参数改变后旧 cursor 返回 INVALID_CURSOR。
  • 成功响应带 host_id；错误使用统一 {code,message,details,request_id,host_id?}。未知、不支持和读取失败使用 null，不得用 0 代替。
  • 大范围时序查询必须指定 resolution=raw|10s|1m|5m；服务端可返回更粗但不得更细的实际 resolution，并拒绝超过 5000 点的请求。

2. 服务与主机

方法与路径用途
GET /health/live进程存活，不访问数据库。
GET /health/ready数据库可读、生命周期初始化完成。
GET /api/v1/statushost_id、hostname、lifecycle_key、identity、kernel boot_id、版本、当前生命周期、最后落盘时间、存储使用和 capabilities。
GET /api/v1/latest当前生命周期最近一次成功持久化的系统样本、采样健康与数据完整度；供多主机总览单请求刷新，不返回进程明细。
GET /api/v1/config/public采样周期、Top N、保留预算等非敏感有效配置。

3. 生命周期

schema v3 使用 lifecycle_key 作为路径标识；boot_id 表示 kernel boot ID。旧 boot ID 仅在唯一匹配时兼容，多个容器实例共享 boot ID 时返回 AMBIGUOUS_LIFECYCLE。

方法与路径参数与结果
GET /api/v1/lifecyclestermination, from_ms, to_ms, limit, cursor；按最后观察时间倒序。
GET /api/v1/lifecycles/{lifecycle_key}元数据、摘要、数据范围和存储完整度。
GET /api/v1/lifecycles/{lifecycle_key}/final最后完整快照；支持 count 返回末尾若干快照。
GET /api/v1/lifecycles/{lifecycle_key}/events事件时间线和分页。

4. 快照和序列

方法与路径用途
GET /api/v1/lifecycles/{lifecycle_key}/snapshots按范围列出快照元数据；from_ms,to_ms,detail_level。
GET /api/v1/lifecycles/{lifecycle_key}/snapshots/{snapshot_id}完整系统样本和可选进程/用户明细。
GET /api/v1/lifecycles/{lifecycle_key}/seriesmetrics,from_ms,to_ms,resolution；供趋势图使用。
GET /api/v1/lifecycles/{lifecycle_key}/compareleft_snapshot_id,right_snapshot_id；返回新增、消失及资源增量。

5. 进程与用户

方法与路径用途
GET .../snapshots/{id}/processesdimension=cpu|rss|swap|read|write、user、limit、cursor；返回排行和脱敏命令。
GET .../snapshots/{id}/users该快照各用户聚合排行。
GET .../processes/{pid}必须同时提供 create_time_ms，查询生命周期内该进程轨迹。

省略号表示 /api/v1/lifecycles/{lifecycle_key}。

6.4 Lifecycle、Snapshot 与排行对象

对象必需字段
LifecycleSummaryhost_id、lifecycle_key、boot_id、container_instance_id?、PID 1 指纹、detection_method、detection_confidence、started_at_ms、last_seen_at_ms、ended_at_ms?、termination、snapshot_count、detail_start_at_ms?、retention_state

ProcessSamplepid、create_time_ms、ppid?、uid、username?、comm、state?、threads?、cpu_percent?、rss_bytes?、swap_bytes?、read_bps?、write_bps?、cmdline_redacted、cmdline_hash、truncated、redaction_status
ProcessRankdimension、rank、value、process；value 与该 dimension 单位一致
UserSampleuid、username?、cpu_percent?、rss_bytes、swap_bytes?、read_bps?、write_bps?、process_count、thread_count
Eventid、lifecycle_key、boot_id、snapshot_id?、occurred_at_ms、type、details

带问号字段允许 null。boot_id 始终表示 kernel boot ID，不能用作容器生命周期唯一键。ProcessSample 的稳定身份是 pid + create_time_ms；username 不参与身份判断。cmdline_redacted 最大 4096 UTF-8 字节，API 不存在获取原始命令的参数或高权限端点。完整 system 字段清单必须由 FastAPI OpenAPI schema 生成并作为实现合同提交。

6.5 SeriesResponse 与 CompareResponse

SeriesResponse {
  host_id, lifecycle_key, boot_id, requested_resolution, actual_resolution,
  series: [{metric, unit, points: [[timestamp_ms, value_or_null], ...]}]
}
CompareResponse {
  host_id, lifecycle_key, boot_id, left_snapshot_id, right_snapshot_id,
  system_deltas: [{metric, unit, left?, right?, absolute_delta?, percent_delta?}],
  processes: {created:[], exited:[], continued:[], pid_reused:[]},
  users: []
}

时间缺口必须包含 null 点或拆分序列，不能由后端插值。基数为 0 或任一侧缺失时 percent_delta 为 null。

6.6 错误合同

第一版后端固定错误码：INVALID_ARGUMENT、INVALID_CURSOR、NOT_FOUND、AMBIGUOUS_LIFECYCLE、DATA_REMOVED、CAPABILITY_UNAVAILABLE、QUERY_TOO_LARGE、BUSY、INTERNAL_ERROR。HTTP 状态码遵循语义；错误 message 用于人类阅读，前端逻辑只依赖 code。Ingress 产生的 401/403/5xx 不保证符合该 JSON 错误结构，前端按网关错误单独处理。

7. 页面与接口映射

页面最小请求
多主机总览每个后端并行请求 status + latest；两者可并行，任一成功都展示可用部分。
主机详情status、latest、lifecycles。
生命周期详情lifecycle、series、events；点击快照后请求 processes/users。
最终证据final?count=N；响应内嵌 system、top 和 users。
快照对比compare；不要求前端下载两个完整快照后自行计算。

9. 安全与浏览器访问

  • 只返回脱敏且最多 4096 字节的命令；原始命令不存储，API 不提供恢复能力。
  • 浏览器通过各主机 HTTPS Ingress 直接跨域访问。后端不实现登录、会话、Cookie 或 Bearer Token 鉴权。
  • CORS 仅允许配置的前端精确 Origin，允许 GET/OPTIONS 和 Content-Type、X-Request-ID；Access-Control-Allow-Credentials 为 false，不允许通配 Origin。
  • Ingress 和网络策略必须限制未受信客户端的可达性。CORS 只约束浏览器脚本，不能阻止 curl 或服务端请求。
  • 设置查询超时、并发上限、响应体上限和请求 ID；慢查询不得饿死采集写入。
